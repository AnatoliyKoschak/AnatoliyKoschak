# Проектирование витрины расчётов с курьерами (`cdm.dm_courier_ledger`)

## 1. Список полей, необходимых для витрины

Для построения ежемесячной отчётной витрины расчётов с курьерами требуются следующие поля:

* `id` — идентификатор записи (суррогатный первичный ключ).
* `courier_id` — ID курьера из системы-источника, которому перечисляется оплата.
* `courier_name` — Ф. И. О. курьера.
* `settlement_year` — год отчётного периода.
* `settlement_month` — месяц отчётного периода (от 1 до 12).
* `orders_count` — количество доставленных заказов за расчётный месяц (определяется по дате создания заказа).
* `orders_total_sum` — общая стоимость заказов за период.
* `rate_avg` — средний рейтинг курьера за расчётный месяц по оценкам пользователей.
* `order_processing_fee` — сумма, удержанная компанией за обработку заказов (`orders_total_sum * 0.25`).
* `courier_order_sum` — сумма выплаты курьеру за доставленные заказы с учётом его среднего рейтинга `rate_avg` и минимального порога за каждый заказ.
* `courier_tips_sum` — общая сумма чаевых, оставленных пользователями курьеру.
* `courier_reward_sum` — итоговая сумма к перечислению курьеру (`courier_order_sum + courier_tips_sum * 0.95`).

## 2. Таблицы слоя DDS, необходимые для построения витрины

Для расчёта метрик витрины используются как уже существующие в хранилище таблицы детального слоя, так и новые сущности для данных курьерской службы.

### Таблицы, которые уже есть в хранилище:
* **`dds.dm_orders`** — содержит информацию о заказах:
  * `id` — внутренний идентификатор заказа для связи с фактами доставок.
  * `order_key` — бизнес-ключ заказа из системы-источника для сопоставления с API.
  * `timestamp_id` — ссылка на время создания/оформления заказа.
  * `order_status` — статус заказа (для фильтрации успешно завершённых заказов).
* **`dds.dm_timestamps`** — содержит календарные атрибуты заказа (используется для определения отчётного года `year` и месяца `month` строго по дате заказа, а не доставки).
* **`dds.fct_product_sales`** — содержит суммы по позициям заказа (`total_sum`), из которых складывается общая стоимость заказа `orders_total_sum` (альтернативно сумма заказа может браться из факта доставки, если они идентичны).

### Недостающие таблицы, которые необходимо создать:
* **`dds.dm_couriers`** (измерение курьеров):
  * `id` — суррогатный первичный ключ.
  * `courier_id` — уникальный ID курьера из API.
  * `courier_name` — Ф. И. О. курьера.
* **`dds.fct_deliveries`** (таблица фактов доставок):
  * `id` — суррогатный первичный ключ.
  * `delivery_id` — уникальный ID доставки из API.
  * `order_id` — внешний ключ (FK) на `dds.dm_orders(id)`.
  * `courier_id` — внешний ключ (FK) на `dds.dm_couriers(id)`.
  * `delivery_ts` — дата и время фактической доставки.
  * `rate` — оценка курьера пользователем за доставку (от 1 до 5).
  * `sum` — сумма заказа.
  * `tip_sum` — сумма чаевых курьеру.

## 3. Сущности и поля, которые необходимо загрузить из API

Из трёх доступных в спецификации методов (`/restaurants`, `/couriers`, `/deliveries`) метод `/restaurants` не используется, так как справочник ресторанов уже загружается в хранилище из MongoDB.

Для наполнения недостающих таблиц DDS из API загружаются следующие две сущности:

### 1. Курьеры (метод `GET /couriers`)
* `_id` — уникальный идентификатор курьера (бизнес-ключ для `dds.dm_couriers.courier_id`).
* `name` — Ф. И. О. курьера (для `dds.dm_couriers.courier_name`).

### 2. Доставки (метод `GET /deliveries`)
* `delivery_id` — уникальный идентификатор доставки (бизнес-ключ для `dds.fct_deliveries.delivery_id`).
* `order_id` — идентификатор заказа из системы заказов (для поиска связи с `dds.dm_orders.order_key`).
* `order_ts` — дата и время создания заказа.
* `courier_id` — идентификатор курьера (для поиска связи с `dds.dm_couriers.courier_id`).
* `delivery_ts` — дата и время доставки (используется для инкрементальной выгрузки через параметры `from` и `to`).
* `rate` — рейтинг доставки (для расчёта `rate_avg`).
* `sum` — стоимость заказа (для расчёта `orders_total_sum` и процента выплаты курьеру).
* `tip_sum` — сумма чаевых (для расчёта `courier_tips_sum`).
