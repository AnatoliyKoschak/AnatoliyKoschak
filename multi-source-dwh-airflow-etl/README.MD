# Многослойное хранилище данных (DWH) и ETL-пайплайны на Apache Airflow

Комплексный проект по построению корпоративного хранилища данных (архитектура `STG -> DDS -> CDM`) для агрегатора доставки еды. Реализована автоматическая инкрементальная выгрузка данных из 3 разнородных источников (PostgreSQL, MongoDB, REST API) и расчет финансовых витрин для взаиморасчетов с ресторанами и курьерами.

## Бизнес-задача
Сервису доставки требовалось автоматизировать ежемесячные финансовые расчеты с партнерами и курьерами на основе данных из трех изолированных микросервисов:
1. **Сервис заказов (MongoDB):** данные о пользователях, ресторанах, меню и составе заказов.
2. **Бонусная система (PostgreSQL, паттерн Outbox):** транзакции списания и начисления бонусных баллов.
3. **Служба доставки (REST API):** данные о курьерах, доставках, оценках клиентов и чаевых.

## Стек технологий
* **Языки:** Python 3, SQL (PostgreSQL)
* **Оркестрация и ETL:** Apache Airflow (DAGs, Hooks, XCom, управление состоянием через `srv_wf_settings`)
* **Источники и БД:** PostgreSQL, MongoDB (`pymongo`), REST API (`requests`)
* **Архитектура DWH:** 3 слоя (`STG`, `DDS`, `CDM`), модель «Звезда», версионность данных **SCD Type 2** (`active_from` / `active_to`), идемпотентная загрузка (`ON CONFLICT`).

## Архитектура и слои данных
1. **Staging-слой (`stg`):**
   * Инкрементальная выгрузка данных из MongoDB (по `update_ts`), PostgreSQL Outbox (по `id` события) и REST API (по пагинации и дате доставки).
   * Хранение курсоров последней успешной загрузки в служебной таблице `srv_wf_settings` для защиты от дублей и потери данных при сбоях.
2. **Detailed Data Store (`dds`):**
   * Нормализованная модель данных (таблицы фактов `fct_product_sales`, `fct_deliveries` и измерений `dm_users`, `dm_restaurants`, `dm_products`, `dm_couriers`, `dm_timestamps`).
   * Поддержка историчности цен и названий блюд по стандарту **SCD Type 2**.
3. **Common Data Marts (`cdm`):**
   * `cdm.dm_settlement_report` — ежедневная витрина взаиморасчетов с ресторанами (выручка, оплата бонусами, комиссия сервиса 25%, итоговая сумма к выплате).
   * `cdm.dm_courier_ledger` — ежемесячная витрина для начисления выплат курьерам (расчет ставки в зависимости от среднего рейтинга, учет чаевых и комиссии).

## Структура репозитория
* `dags/` — DAG-файлы Apache Airflow для послойной загрузки данных (`stg_*`, `dds_*`, `cdm_*`).
* `dags/lib/` — модули подключения к внешним источникам (`mongo_connect.py`, `pg_connect.py`).
* `dags/ddl/` — SQL-скрипты создания схем, таблиц, индексов и ограничений целостности (`CHECK`, `UNIQUE`, `FK`).
* `dags/dml/` — SQL-скрипты трансформации данных и наполнения слоев DDS и CDM.
